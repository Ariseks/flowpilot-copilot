# FlowPilot Copilot｜面试追问与回答

## 1. 这和普通知识库聊天有什么区别？

普通知识库聊天止于“检索—回答”。本项目增加了受控任务路由、专用结构化产物、引用展开、离线评估、用户反馈、知识缺口和运营看板，形成从使用到优化的闭环。

## 2. 为什么选择这个业务场景？

SaaS 产品运营同时具备高频知识问答、客服协作、反馈分析和运营方案需求，既能展示 RAG/Agent 工程，也能展示产品边界与运营指标，比纯技术问答更贴近目标岗位。

## 3. RAG 的完整流程是什么？

文档导入 → 清洗与切分 → 词项/Embedding 表示 → 建立索引 → 查询处理 → top-k 召回 → 可选重排 → 证据组装 → 受约束生成 → 引用返回 → 反馈与评估。

## 4. 当前为什么用 TF-IDF，不用向量数据库？

MVP 需要零服务依赖、结果可解释、离线稳定。产品名、套餐、错误描述等关键词密集内容适合稀疏检索。但它不擅长语义改写，生产版会采用 BM25/TF-IDF + Dense Embedding 混合召回并加 Reranker。

## 5. 中文 TF-IDF 怎么处理？

当前提取中文单字、连续 bigram 和英文/数字词项，使短文本和专有名词有可匹配信号。生产环境可改用结巴/领域词典、BM25，以及中文 Embedding 模型。

## 6. Chunk Size 和 Overlap 怎么选？

不是固定越大越好。太小会丢上下文，太大则噪声高、成本高。我会根据文档结构先按标题/段落切，再用长度窗口兜底，通过评估集比较不同 chunk size、overlap 对命中率和答案忠实度的影响。

## 7. top-k 越大越好吗？

不是。过小可能漏证据，过大会引入冲突和噪声，也增加 token 成本。应先提高召回，再用重排控制进入模型的上下文数量，并按问题类型动态设置。

## 8. 如何减少幻觉？

检索前做权限和元数据过滤；生成时要求仅依据证据并允许拒答；输出带逐条引用；对关键字段做结构化校验；离线评估 Faithfulness 和 Citation Correctness；高风险外部操作加入人工确认。

## 9. 如果检索到互相冲突的文档怎么办？

保留版本、发布时间和权威级别元数据，优先最新且权威来源；检测冲突后不直接合并事实，而是显式提示差异并引用双方。知识运营侧把冲突加入待治理列表。

## 10. 为什么叫 Agent，而不是几条 Chain？

它存在意图判断、路径选择、状态步骤和不同产物节点，但自主性受到约束。严格来说它是 workflow-oriented agent，而不是完全自主 Agent。这样表述更准确，也更适合企业应用。

## 11. 为什么不让 LLM 自己选工具？

LLM 路由灵活，但有随机性、成本和 Prompt Injection 风险。当前四类任务边界清晰，用规则与显式选择更稳定。未来任务增多后可采用“规则优先 + 模型分类 + 低置信人工选择”的混合路由。

## 12. LangChain 在生产版中放在哪里？

将自定义检索器包装为 BaseRetriever，使用文档 Loader/Splitter 和 Runnable 组合检索生成链；但保留业务模型与框架解耦，避免核心领域逻辑被框架类型侵入。

## 13. LangGraph 能解决什么？

它适合有状态、多分支、可恢复的长流程：条件边、节点重试、检查点、人工审批、失败恢复。活动发布或客服工单写回等带副作用流程，使用 LangGraph 比自由 ReAct 更可控。

## 14. 如何评估 RAG？

拆层评估。检索层看 Hit Rate、Recall@k、MRR、nDCG；生成层看 Faithfulness、Answer Relevance、Citation Correctness；系统层看延迟、成本、失败率；业务层看解决率、点踩率、转人工率和任务完成率。

## 15. 测试集从哪里来？

冷启动从产品 FAQ、客服高频问题和边界案例构造 Golden Dataset，上线后将低分问答、无命中查询、人工改写结果持续回流。测试集需版本化，并按产品模块、难度和风险分层。

## 16. RAGAS 有什么局限？

LLM-as-a-judge 会受评审模型偏差、Prompt、语言和领域影响，且成本不低。不能只看一个综合分；应配合人工抽检、确定性规则、检索指标和真实在线反馈。

## 17. 如何防 Prompt Injection？

把文档内容视为不可信数据，明确隔离系统指令与检索内容；工具使用白名单和最小权限；外部 URL/附件做安全处理；输出做 schema 验证；敏感操作需确认；记录每次工具调用用于审计。

## 18. 多租户怎么做权限？

文档入库时绑定 tenant、workspace、ACL 和敏感等级；查询时在召回阶段强制过滤，不能检索后再遮盖。数据库采用行级安全或租户隔离，缓存键和向量索引也必须包含租户维度。

## 19. JSON 存储有什么问题？

并发写、事务、查询、权限和扩展能力有限，只适合单机 MVP。生产版使用 PostgreSQL 存业务数据，对象存储保存原文，向量扩展或专用向量库保存 Embedding，Redis 处理缓存与任务状态。

## 20. 文档更新如何保持索引一致？

为文档建立版本和内容哈希；解析任务幂等；先写新索引再原子切换版本；删除旧 chunk；记录失败重试和死信队列。对增量更新只重建变化片段。

## 21. 如何做流式输出？

FastAPI 可用 SSE 返回节点事件和 token；前端按 `route/retrieve/rerank/generate/done/error` 事件更新步骤。需要处理断线重连、请求取消、重复事件和最终结果落库。

## 22. 如何优化延迟和成本？

查询归一化缓存；Embedding/检索并行；减少进入 LLM 的片段；小模型做路由和重写，大模型仅处理复杂生成；流式返回改善感知延迟；设置 token、模型和工具预算。

## 23. 为什么前端还保留 Mock 降级？

面试现场网络和模型服务不稳定，降级保证可展示信息架构。但 UI 明确显示“API 已连接”或“演示数据”，不把 Mock 冒充真实结果。正式环境可关闭该降级并展示错误重试。

## 24. 项目最大的不足是什么？

当前语义召回、文档解析、权限、可观测和持久化仍是 MVP；评估集规模有限；没有真实用户业务指标。我会明确这些边界，并给出按风险和价值排序的迭代计划，而不是声称已经生产可用。

## 25. 如果只能再做一个功能，你会做什么？

优先做“失败案例回放台”：保存查询、召回片段、分数、Prompt/模型版本、答案和反馈，可对同一案例切换检索配置重跑。它直接提升调试与迭代效率，比先堆更多 Agent 工具更有价值。
