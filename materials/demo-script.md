# FlowPilot Copilot｜7 分钟面试演示脚本

## 演示前准备

- 本地启动：`backend/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8011`
- 或容器启动：`copy backend/.env.example backend/.env` 后执行 `docker compose up --build -d`；已在本机 Docker Desktop 验证构建、启动与就绪检查。
- 浏览器打开：`http://127.0.0.1:8011`
- 启动前可请求：`http://127.0.0.1:8011/api/health/ready`；返回 `status: ok` 后开始演示。
- 右上角看到“API 已连接”，说明当前不是前端 Mock。
- 当前本地配置使用小米 MiMo 普通 API 的 `mimo-v2.5-pro`；`sk-` Key 与 `https://api.xiaomimimo.com/v1` 已完成最小请求验证。若改用 Token Plan，必须同时替换为匹配的 `tp-` Key 和 Token Plan 地址。若现场网络或额度异常，后端会基于真实检索证据降级，不使用前端伪造成功。移除 `LLM_API_KEY` 后可回到稳定的 deterministic Demo 模式。

## 0:00—0:40｜问题与定位

**台词：**

“这不是一个普通的 PDF Chat。我的目标是解决 SaaS 团队三个问题：资料分散、生成结果不可追溯、低质量回答没有运营闭环。FlowPilot Copilot 把产品文档、FAQ、工单和运营规范变成可检索知识，再通过受控 Agent 完成不同业务任务；每次调用都保留引用和 Trace，低分反馈会回流成待补知识信号。”

## 0:40—2:00｜演示 1：可追溯知识问答

进入“Copilot 对话”，任务类型选“知识问答”，输入：

> 专业版的任务运行次数怎么计算？额度用完后会怎样？

**展示重点：**

1. 展开“Agent 执行过程”：意图路由 → 知识检索 → 结构化产物。
2. 指出回答不是裸文本，引用包含来源、片段 ID 和相关度。
3. 展开计费 FAQ 和产品概览引用，核对事实。

**台词：**

“检索层会对中文做字符和 bigram 词项处理，同时运行 TF-IDF 余弦与 BM25 两路召回，再用 RRF 融合排序。界面显示的相关度仍是可解释的 TF-IDF 分数，所以无证据阈值不会被融合权重污染。当前不依赖外部向量服务；后续再用 Golden Dataset 验证 Embedding 和 Reranker 是否真的带来提升。证据不足时系统明确说不知道，而不是补全想象。”

## 2:00—3:20｜演示 2：Agent 不是换 Prompt

任务类型选“用户研究”，输入：

> 分析近期用户反馈，给出最优先解决的三个问题。

**展示重点：**

- 后端路由到 `feedback_analysis`。
- 结合站内反馈和客服工单生成结构化报告。
- 展示平均评分、问题分布、发现和建议（界面以摘要/关键发现呈现）。

**台词：**

“我没有让模型自由决定所有工具，而是采用受控路由。企业运营场景里，可预测、可审计通常比完全自主更重要。四个意图各有专用产物结构，后续外部写操作还要经过人工确认。”

## 3:20—4:20｜演示 3：运营方案生成

任务类型选“内容生成”，输入：

> 为还没有发布首个流程的试用用户，设计一个 7 天激活活动。

**展示重点：**

- 路由到 `campaign_plan`。
- 结果覆盖人群、价值主张、渠道、节奏、指标和 A/B 实验。
- 引用运营活动规范，说明文案不得承诺未上线功能。

## 4:20—5:20｜知识更新闭环

进入“知识库” → “导入知识”，名称填“8 月功能更新”，内容示例：

> FlowPilot 8 月新增流程文件夹功能。专业版和企业版用户可以创建文件夹，并批量移动最多 50 个流程。免费版仅支持查看示例文件夹。

导入后回到问答，输入：

> 流程文件夹支持哪些套餐？一次最多移动多少个流程？

**台词：**

“导入不是前端假动作：后端写入 JSON 后会重新切分并重建索引，新知识立即进入检索。”

## 5:20—6:10｜真实反馈、Trace 与评估

- 点击回答下方“需改进”；该反馈会携带当前 `task_id` 写入后端。
- 进入“运营洞察”，展示由任务、检索分数、模型降级状态与关联反馈生成的低分复盘和待补知识信号。
- 指出回答底部 Trace：总耗时、检索耗时、Top-1 分数、是否走规则降级。
- 进入“Agent 流程”，按任务类型或“仅看本地规则降级”筛选任务，点“回放”打开一条完整 Trace。
- 进入“评估中心”，运行 20 条版本化回归集，并打开结果详情查看每条 Case 的规则评估。

**台词：**

“RAG 上线只是开始。这里的反馈不只是计数，而是关联到具体任务；我能通过 Trace 判断问题来自无证据、低相关度、模型降级还是用户对表达不满意。评估集也不是 3 条硬编码题，而是版本化的 20 条案例：同一批 Case 同时跑 TF-IDF 基线和 Hybrid RRF，对比来源命中与 MRR；另外检查关键词召回、资料外拒答、引用来源是否正确，以及回答主张是否被引用片段覆盖。离线评估固定用检索证据生成确定性回答，避免云模型波动干扰回归结果。”

## 6:10—7:00｜交付、架构与诚实边界

**展示重点：**

- 可选打开 `/api/health/ready` 或 `/api/metrics`，说明进程已就绪、可查看请求量和延迟快照。
- 说明项目已提供 Docker Compose：前端多阶段构建、后端非 root 运行、`flowpilot-data` 命名卷保存运行状态。

**台词：**

“当前是面试 MVP：React + FastAPI，本地 JSON 持久化，自实现 TF-IDF + BM25 / RRF 的可解释检索，再用 LangChain Core 的 Document 和 Runnable 适配成标准 retrieve→generate 链路；LLM 走 OpenAI-compatible 适配器。交付上我补了 Docker Compose、存活/就绪检查、JSON 请求日志、进程内指标和单机限流；运行状态独立放到命名卷，避免重建容器丢数据，也不会覆盖镜像里的种子资料。文档已经支持 TXT、Markdown、CSV、可提取文本的 PDF 和 DOCX。项目没有虚构已使用 LangGraph。生产化时会先用现有评估集验证 Embedding、Reranker 是否有效，再按真实业务需求加入 LangGraph 审批状态、OCR 异步解析、权限隔离和人工标注评估。”

## 现场兜底

- 若模型 API 不可用：Demo 模式按检索证据生成确定性结果，主链路不受影响；前端真实请求超时为 60 秒，覆盖后端最多 45 秒的模型调用等待。
- 若后端未启动：前端自动回退 Mock，但应主动说明；正式演示优先确保右上角显示“API 已连接”。
- 若被追问真实效果：只说当前测试结果和架构，不编造业务提升；线上指标需采集真实用户数据。
